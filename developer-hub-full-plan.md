# Developer Hub - Full Product & Engineering Plan

> A free, developer-first platform where developers can discover,
> compare, understand, save, and use the tools, services, resources,
> libraries, learning material, utilities, and platforms they need
> across the entire software-development lifecycle.

------------------------------------------------------------------------

# 1. Product Vision

The product is **not just a directory of developer tools**.

It is a centralized **Developer Resource & Tool Discovery Platform**.

A developer should be able to come to one place and answer:

-   What should I use for this?
-   Is there a free option?
-   Is it open source?
-   Can I self-host it?
-   Does it have an API?
-   What are the alternatives?
-   What works well with my current stack?
-   What tools do I need to build a SaaS?
-   Where can I learn this?
-   Where can I take notes or document my project?
-   Is there a utility I can use right now?

Core workflow:

**Discover -\> Understand -\> Compare -\> Choose -\> Build -\> Save -\>
Share**

The long-term goal is:

> **"Everything developers need to build software, in one place."**

------------------------------------------------------------------------

# 2. Product Principles

1.  Browsing and discovery are free.
2.  No account is required to browse.
3.  Search must be fast and useful.
4.  Information must be structured, not just a collection of links.
5.  Tool information should be accurate and verifiable.
6.  Pricing/free-tier information must be clearly separated.
7.  Sponsored content must always be labeled.
8.  Organic rankings should not simply be sold.
9.  Quality is more important than raw number of listings.
10. The platform should be useful on desktop and mobile.
11. The product should feel like a developer workspace/index, not a
    generic SaaS landing page.
12. Avoid unnecessary animations and visual noise.
13. Prefer official sources when verifying information.
14. If information is unknown, mark it unknown/unverified instead of
    inventing it.
15. Start as a modular monolith and only introduce infrastructure when
    it is actually needed.

# 7. Architecture Philosophy

Use a **modular monolith**.

Do NOT build:

-   Microservices
-   Kubernetes
-   Kafka
-   Event-driven infrastructure
-   Multiple backend services
-   Complex queues

for V1.

Initial architecture:

``` text
                    NEXT.JS
                       |
        +--------------+--------------+
        |                             |
      PUBLIC                        ADMIN
        |                             |
        +--------------+--------------+
                       |
                SERVER / API
                       |
                   MONGOOSE
                       |
                 MONGODB ATLAS
                       |
          +------------+------------+
          |            |            |
        TOOLS      CATEGORIES      TAGS
```

Later:

``` text
MongoDB Atlas Search
        |
Semantic Search
        |
Recommendation Engine
        |
Verification Automation
```

# 11. Tool Model

The Tool model is the core of the product.

``` ts
{
  _id,

  name,
  slug,

  description,

  websiteUrl,
  logoUrl,

  categories: [ObjectId],
  subcategories: [ObjectId],
  tags: [ObjectId],

  pricing: {
    type:
      "free"
      | "freemium"
      | "paid"
      | "open_source"
      | "free_trial"
      | "contact_sales",

    hasFreeTier: Boolean,

    freeTier: {
      available: Boolean,
      description: String,
      creditCardRequired: Boolean,

      limits: [
        {
          metric: String,
          value: String
        }
      ]
    },

    startingPrice: Number,
    currency: String,

    billingPeriod:
      "monthly"
      | "yearly"
      | "one_time"
      | null
  },

  openSource: {
    isOpenSource: Boolean,
    githubUrl: String,
    license: String
  },

  capabilities: {
    apiAvailable: Boolean,
    selfHostable: Boolean,
    commercialUse: Boolean,
    mobile: Boolean,
    web: Boolean,
    desktop: Boolean,
    cli: Boolean
  },

  technologies: [String],

  integrations: [String],

  bestFor: [String],

  alternatives: [ObjectId],

  relatedTools: [ObjectId],

  featured: Boolean,

  sponsored: Boolean,

  status:
    "draft"
    | "published"
    | "archived",

  verification: {
    status:
      "verified"
      | "needs_review"
      | "unverified",

    lastVerifiedAt: Date,

    verifiedBy: ObjectId
  },

  stats: {
    views: Number,
    outboundClicks: Number,
    bookmarks: Number
  },

  createdAt,
  updatedAt
}
```

Important indexes:

-   slug
-   status
-   categories
-   tags
-   pricing.type
-   pricing.hasFreeTier
-   openSource.isOpenSource
-   capabilities.selfHostable
-   featured
-   verification.lastVerifiedAt

  ],

    "verified"

``` text

September 29, 2026
```

# 19. Pricing Data

Do not reduce pricing to:

``` text
free: true
```

Use:

``` text
FREE
FREEMIUM
PAID
OPEN SOURCE
FREE TRIAL
CONTACT SALES
```

Distinguish:

-   Free forever
-   Free tier
-   Free trial
-   Open source
-   Self-hosted
-   Paid

Never call a limited free trial "free forever."

# 67. Final Engineering Rule

The platform should be built as a **data-driven product**.

Do not hardcode resources into React components.

Bad:

``` tsx
const tools = [
  {
    name: "Supabase",
    ...
  }
]
```

Good:

``` text
MongoDB
   |
Mongoose
   |
API
   |
Server Component
   |
Reusable UI
```

The admin dashboard should control the content.

Adding a new tool should NOT require changing frontend code.

The process should be:

``` text
Admin
  |
Create Tool
  |
Fill metadata
  |
Select categories
  |
Select tags
  |
Add pricing
  |
Publish
  |
Tool immediately appears
in relevant lists/search/category pages
```

This is critical.
